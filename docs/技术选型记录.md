## 2. 关键自研决策

### 2.1 镜头检测：不引入 PySceneDetect，改用 FFmpeg 场景得分 + 自适应阈值

- 做法：`ffmpeg -vf "scale=160:-2,select='gte(scene,0)',metadata=print:file=-"` 逐帧输出内容变化量，
  再以 `mean + k·std`（夹在 [0.08, 0.60]）作为阈值，局部极大值 + 最小镜头时长合并，转场单列。
- 理由：
  1. 只依赖 FFmpeg（部署已必需），不新增 GPL/BSD 依赖与权重条款；
  2. 输出的是**逐帧分数序列**，阈值可配置可复现，便于按文档 §7.1 做阈值冻结；
  3. PySceneDetect 仍是**候选**（BSD-3-Clause），若后续自研阈值在留出集上不达标，
  可在 `app/pipeline/scenes.py` 后面接适配器替换，接口不变。
- 未验证：本方案尚未在授权留出集上测 F1，**不能声称达到 0.85**。

### 2.2 语音：先做"诚实的空实现"，不自造台词

- `asr_provider=none` 时，转写为空并在记录里写明原因；无音轨素材同样返回空。
- 候选 faster-whisper / 托管 ASR 通过 `app/providers/asr_http.py` 接入（HTTP + verbose_json）。
- 理由：文档 §4.1 明确"无人声时转写为空，不根据音乐臆造台词"。

### 2.3 视觉分析：供应商适配器 + 离线确定性实现

- `openai_compatible`：任意 OpenAI 兼容多模态接口，帧以 base64 data URI 传入，强制 JSON 输出；
- `offline`：只输出可核对的统计（时间区间、时长、代表帧数、平均色、帧间像素差），
  景别/运镜一律 unknown，并在报告与 UI 中标注 provider=offline；
- 理由：没有模型密钥时仍要能跑通闭环与回归测试，同时**不能把假结果当真结果**。

### 2.4 队列：数据库队列为默认，Celery 为可选

- 默认用 `jobs` 表 + 独立 Worker 进程（乐观锁领取、心跳、陈旧锁恢复）；
- 优点：零额外依赖即可满足文档 §3.2 的"重启可恢复、不永久处理中"；
- `queue_backend=celery` 时投递到 Redis，消费同一张表，API/Worker 仍分进程。
